# OAC Evidence-Gated Roadmap

OAC advances by evidence gates, not feature count. A later layer cannot repair missing semantics,
authority, or independence in an earlier layer. Evidence produced by an external reference runtime
does not silently become evidence owned by the standard.

## What E0b closes

Spec 009 names only the minimum portable lifecycle records:

```text
OrganizationSnapshot + SourceAdmissionReceipt + OrganizationalDemand + SemanticChangeSet
  -> OrganizationPlan + PlanCertificate
  -> runtime-owned ExecutionReceipt reference
  -> OutcomeCertificate
  -> candidate evolution references
  -> SourceAdmissionReceipt for an immutable successor
```

It also defines deterministic, domain-separated `S/D/P/X/O/E` roots. Missing, duplicate,
cross-namespace, stale, digest-invalid, self-certified, or illegally promoted material fails closed.

E0b does **not** add a scheduler, handler registry, workflow DSL, connector, enterprise IAM, observation
producer, Procedure format, governance transaction, or active pointer to OAC. Those are implementation
responsibilities. The profile permits only zero-effect references in its current version.

## How the external OrgRebase result should be read

The peer OrgRebase repository uses public OAC wire resources and CLI boundaries to run:

```text
admitted Source/Demand
  -> BASE and SPLIT contract-valid Plans
  -> runner-owned zero-effect Execution
  -> controlled Observation
  -> independent Outcome ACCEPT/REJECT
  -> topology-independent Procedure candidate
  -> governance approval of prepared exact bytes
  -> immutable Profile/Snapshot successor
  -> pointer rollback
```

This closes one controlled integration coordinate that OAC itself intentionally does not own.
It proves that the minimum profile is usable by one external reference product. It does not prove:

- externally authenticated enterprise Source;
- external human governance review;
- qualified domain Ground Truth;
- portability across two independently maintained runtimes;
- positive business effect or cross-enterprise generalization;
- production IAM, safety, high availability, or authorization.

Historical Specs 004–006 are not retroactively marked implemented by this external synthetic journey.

## Why the order still matters

Runtime breadth before semantic and authority closure scales ambiguity. Learning before independent
outcome evidence optimizes against self-reported success. Generalization claims before external
implementations and real enterprise observations confuse one reference with a standard.

The next evidence sequence is:

```text
freeze and replay E0b from a clean archive
  -> externally maintained semantic implementation
  -> qualified human evidence and adjudication
  -> disposable real-enterprise Shadow mapping
  -> governed cross-case candidate evaluation
  -> only then consider production profiles
```

## Persistent bounded evidence

M1 remains bounded to the published Supplier Profile. SC-003 through SC-007 retain candidate
obligation types that the frozen Profile does not derive; OAC will not add answer-shaped special cases.

M2 remains internally generated and same-repository. The bounded semantic matrix and fixed-Plan relation
provide useful mutation and differential falsification, but not legal clean-room independence, verifier
completeness, or certification.

R1 remains one synthetic controlled reference. The strongest combined product claim is one complete
OAC reference loop plus byte-exact regression of OrgRebase's preliminary Quote loop. It is not evidence
that two enterprises completed the same lifecycle or that OAC can automatically adapt to any enterprise.
