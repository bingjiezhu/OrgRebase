# 效果提交与对账

`CommitGateway` 是所有新外部效果的持久提交入口。当前真实适配器是本地 Git，证据范围为 `LOCAL_REAL_TOOL`；尚未有已完成真实客户沙箱资格的 CPQ 草稿写回适配器。生产的只读来源接入不能据此获得外部写权限。

`EffectRequest` 绑定租户、稳定效果 ID、目标、动作、精确前置版本、批准摘要及载荷。尝试次数、worker 与租约不进入业务请求摘要。同一 ID 改内容会拒绝。

只有 `READY` 可以发出新请求。`DISPATCHING` 在数据库事务中持久化后才进行外部 I/O；中断或异常恢复一律进入只读对账。`COMMIT_UNKNOWN` 保留目标屏障，租约到期不会允许另一个效果绕过去。只有带本次效果身份和请求摘要的正面证据可以确认，空结果、未知返回类型或无对端操作身份都不能计为成功。

对端终态拒绝才能转 `REJECTED`。只有证明旧请求不可能再执行的 `ABSENT_FINAL` 才能回到 `READY`，并在下一次调用重查授权。普通查不到、HTTP 202、网络超时和未分类错误都不构成这种证明。每次确认、工具收据和目标屏障释放属于同一数据库事务。

## Git 的确切保证

Git 适配器在唯一提交模块内执行受限 `downstream/` 文件修改与补偿。新的 commit object 先生成，再用 Git `update-ref` 事务同时检查预期 HEAD、更新分支并创建稳定效果 ref。效果 ref 保留已发生的提交，后续分支移动或正常回收不能把它误判为从未发生。

仓库排他锁由执行子进程继承，因此父进程意外退出时，尚在执行的 Git 进程仍持锁。接手进程必须先获得同一仓库锁，再查询效果 ref；确认没有效果才允许重新准备。同一仓库是锁定的目标范围，不以文件路径绕过仓库并发检查。

对账不修复工作目录、不创建提交。已证明未发生的中断准备可在下一次获准执行时清理本请求的文件；存在其他文件变化时停下交由操作者处理。代码保留路径检查、禁用外部 hooks、最小子进程环境以及精确 blob 验证。

历史 `external_operation_journal` 不再写入新状态。已记录的旧收据可离线读取；未完成的旧协议记录明确要求单独迁移/核对，不自动当成新请求重发。这是历史数据读取边界，不是第二个活动 writer。

本地 Git 工具的受控 executor 身份不等同于企业 IdP。真正的 CPQ 适配器还需证明目标原子条件写、效果查询、授权语义及幂等保留期限，才可启用那个动作；本地数据库 fencing 不能替目标提供这些保证。
