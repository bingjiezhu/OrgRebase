# 企业运维观察与数据退出

运维以规范存储和实际效果回执为依据。产品提供有界观测接口，部署方接入已有采集与告警系统；不再引入另一个具有业务写权限的观测平台。

## 当前运行观察

经过身份与工作区权限验证的 `GET /api/workspace/operations?after=0&limit=100` 返回以下信息：

| 数据 | 解释 |
|---|---|
| unresolved changes | 尚未处置的变更计数，包含需要重新规划或拒绝的过期/陈旧事项 |
| effect counts | READY、DISPATCHING、COMMIT_UNKNOWN、CONFIRMED、REJECTED 的本工作区聚合 |
| UNKNOWN 年龄 | 同一数据库快照中全部 UNKNOWN 的最老观测年龄；`unknown_age_sample_limit` 为 null，`unknown_age_sample_complete` 为 true，不受事件分页条数限制 |
| source coverage | 当前来源覆盖状态、水位时效、摘要和失败原因，不包含原始来源内容 |
| review observations | 客户端报告的主动审阅时长，有唯一持久事件；不是独立测量的真实工时 |
| elapsed latency | 具备真实服务端时钟证据时，报告提交到预演、预演到批准的经过时长 |
| event cursor | 最多 100 条事件的采集进度，消费者持久保存游标，按事件序号/摘要去重 |

经过时长包含排队与人工等待，不等于模型耗时或主动劳动时间。冻结时钟的测试不生成真实延迟。指标只有固定状态等低基数标签，组织、运行、actor、目标和原文不进入指标标签。完整审计链验证是显式离线/归档动作；这个接口的 `APPEND_PROJECTION_ONLY` 不冒充全历史审计。

审阅观察保留变更 ID、观察引用和摘要、操作及结果。旧事件没有操作或结果时返回 `null`，不补造历史。当前页面每次人工操作只记录上次操作后新增的主动审阅时间；批准后的自动应用记录为零新增审阅时间，失败重试也不会重复累计前一次审阅。旧版页面可能发送累计计时，分析历史记录时须核对客户端版本，不能跨版本直接求和。网络丢失的计时不能恢复为零劳动成本，客户端计时也不能直接换算为已实现的人力节省。

连续运行的完成观测 v2 使用真实回执统计：例如两个负责人批准一个来源恢复组，计为两次负责人批准和一次报价重建。OTLP 时间是实际读取回执投影的时刻，不合成过去的 span。历史 v1 观测只作为既有证据读取。

## 告警与处置

未分类 HTTP 错误返回稳定代码 `WORKSPACE_REQUEST_FAILED`，并提供服务端生成的
`detail.incident_id` 和同值的 `X-OrgRebase-Incident` 响应头。未被路由处理的异常返回 500；
已经分类的业务拒绝继续使用原错误码和状态。用错误编号在 `orgrebase.http` 服务日志中查找
`request_failed`，可关联异常类型、错误码、HTTP 状态和注册路由模板。默认和子工作区都适用。
日志不包含异常原文、URL 参数、请求体、令牌、客户身份或 traceback 局部变量；不要为排障开启
请求内容的全量记录。非 HTTP 的后台错误投影不生成这类请求日志。

错误编号用于定位请求，不是业务回执或可重试授权。执行请求异常后仍应先回读同一提案和效果状态，
依既有幂等及 UNKNOWN 规则恢复。纯状态读取失败也不能据此推断之前的业务操作未生效。

| 信号 | 责任角色 | 处置 |
|---|---|---|
| `EXTERNAL_OUTCOME_UNKNOWN` | 执行服务运维与原批准负责人 | 查询同一 operation，保留目标屏障；获得正向回执或完成受 fencing 保护的取消后再决策 |
| `SOURCE_COVERAGE_UNKNOWN` | 来源连接器运维与字段负责人 | 恢复当前可见性，完成同步；绑定或字段语义变化后重新确认映射 |
| 数据库或审计检查点不一致 | 数据库与独立审计责任人 | 停止写入晋级，验证原始备份、删除台账及独立锚，不修补历史摘要 |
| 实际目标异常修改 | 目标系统运维与业务负责人 | 依据目标自身审计调查；OrgRebase 的 ETag 条件写与正向回查负责阻止覆盖和确认本次效果 |

当前没有持续订阅任意目标修改的后台监视器，接口明确标为 `NOT_CONTINUOUSLY_MONITORED`。不能把条件写保护宣传为已完成全量目标漂移监控。告警返回责任和动作，不会自动向外发送通知或改变业务状态。

OAC 安装探测最多等待 10 秒，单次编译、校验或降低调用最多等待 60 秒。超时分别返回
`OAC_DISTRIBUTION_PROBE_TIMEOUT` 或 `OAC_CLI_TIMEOUT`；POSIX 部署同时终止启动器及其子进程。
文件结果只有在进程成功退出并解析为有效 JSON 对象后才替换原输出，部分结果和上次结果均不能充当本次校验。
先检查 OAC 安装、锁定依赖和主机负载，再重新发起候选校验；超时不授予批准或生效权。

`enterprise-pilot-check` 的独立复核进程也限定为 60 秒，超时返回
`PILOT_INDEPENDENT_VERIFICATION_TIMEOUT`，不会报告验收成功。保留该次工作目录调查，复验时使用新目录。
以上是本地工具的等待上限，不是生产服务的 SLA。

## 数据退出与服务撤回

退出顺序应明确由客户接受：冻结新的业务批准和执行准入；盘点所有在途和 UNKNOWN 效果；导出已完成业务对象、完整证据及独立审计检查点；按组织留存/删除规则处理私有来源；撤销来源、目标和 IdP 凭据；最后下线服务。任何尚未确认的外部效果必须随退出交接，不得把它从分母或导出清单删掉。

报价与证据导出继续走现有已鉴权 API。内容摘要证明完整性，当前 IdP 授权决定能否导出；历史审批不能替代当前访问权。私有数据按 [留存与删除机制](PRIVATE-DATA-LIFECYCLE.md) 处理，独立删除台账必须覆盖之后恢复的备份。清理私有原文不等于抹掉已发生业务动作的审计责任。

制品通过锁文件、摘要、SBOM、安装验证及 [来源签署与撤回流程](RELEASE-CANDIDATES.md) 交接。GitHub attestation 只有在确实执行的受信构建中才成立；本地测试日志不能当签名。运行授权、来源覆盖和预演按各自期限重新验证，客户资格在 IdP/ACL/映射/目标插件/制品变化时重新检查，不能用永久有效的“企业认证”标签代替。

SLO、支持响应时间、RPO/RTO、数据导出格式接收方及删除后的法定保留范围需要客户签收。这里没有填写虚构 SLA，也没有将本地采样或审阅计时换算成已实现的 ROI。业务收益须用 [完整成本观测](BUSINESS-OBSERVATIONS.md) 的真实基线、失败分母及原始记录另行验收。
