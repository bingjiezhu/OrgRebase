# 报价金额与规则生效演示

`template:enterprise_quote@v2` 在现有报价流程中加入商品明细与计价规则。确定性计价器生成行金额、整单折扣、折后净额、税额与总额；变更预演显示拟议金额，匹配负责人批准后，现有 Rebase 事务写入规则和后继报价。页面只展示服务端保存的结果，不在浏览器另算一套金额。

本例展示的是“同一业务输入，规则变更后执行结果同步更新”。计价是验证这一能力的业务负载。

折扣案例不限定产品范围：当前工作台同样可提出上线日期与产品方案变化，日期变化会保留原金额。
带金额报价暂不支持独立切换币种，需要同时核定明细价格与币种；无金额模板仍支持币种政策变化。
多领域链路、来源变化处理及验证入口见[上游变化复核](UPSTREAM-CHANGE-REVIEW.md)。

## 数据与规则

商品、SKU、数量和原始单价来自 [UCI Online Retail](https://archive.ics.uci.edu/dataset/352/online%2Bretail)，Daqing Chen，DOI `10.24432/C5BW33`，[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)。这是2010–2011年的历史交易，不能称为现时报价或真实客户已经接入。

演示选用固定样本中的发票557670，共6条商品明细，原币种GBP。20%价外税和从0%到10%的整单折扣均为**受控演示规则**，来源未提供实际税费与折扣。客户所在国家不改变币种，不推断汇率或税法。组织、负责人和权限来自测试配置，不是原企业组织。

| 金额项（GBP） | 规则变更前 | 九折规则生效后 |
|---|---:|---:|
| 商品小计 | 1,607.04 | 1,607.04 |
| 折扣金额 | 0.00 | 160.70 |
| 折后净额 | 1,607.04 | 1,446.34 |
| 受控税额 | 321.41 | 289.27 |
| 报价总额 | **1,928.45** | **1,735.61** |

该差额是政策计算结果，不是节省的人工成本或企业ROI。

## 复现准备

在产品仓库根目录运行，使用已安装项目依赖的Python。交付代码已包含[固定公开样本、来源清单及数据许可](../benchmark/public-retail-quote/v1/README.md)，默认校验其SHA-256和字节数，无需先下载完整XLSX。输出目录必须是新目录；这些目录位于产品仓库外。

```bash

ORGREBASE_ENTERPRISE_PACK="$(pwd)/../.runtime/retail-demo-new/pack" \
ORGREBASE_WORKSPACE_DB="$(pwd)/../.runtime/retail-demo-new/demo-workspace.sqlite" \
ORGREBASE_CHANGE_MODEL_PROVIDER=local-deterministic \
.venv/bin/python -m orgrebase.cli serve --local-demo --host 127.0.0.1 --port 8879
```

打开 `http://127.0.0.1:8879/`。`--demo-invoice` 只封装数据，不提前生成报价、批准或写入成功状态。`demo.json` 记录准备时刻的状态和默认8081端口启动命令；上面的命令显式使用8879。

## 页面演示顺序

1. **变化处置 → 需求与当前交付**：填写工作说明，例如“根据已准入商品明细和财务计价规则生成报价，列出数量、单价、折扣、税费和总额”。校验候选、确认范围，再启动任务。
2. 查看**报价金额明细**：6条商品的SKU、明细ID、数量、单价与行金额；当前总额为GBP 1,928.45。在这个UCI适配器中，`row235992`等明细ID对应原工作簿物理行号，不把所有企业的任意明细ID都解释成Excel行号。展开“金额依据与计算口径”核对来源和舍入顺序。
3. **业务数据演化与验收 → 提出变化**：字段选“折扣与税率”，折扣率改为10.00%，税率保留20.00%，税费说明保留“受控演示税率（非历史实际税费）”。来源可填 `source:controlled-demo/uci-557670/discount-10pct`，原因说明这是受控规则变更。
4. 登记提案并**预演影响**：金额表显示旧总额1,928.45和拟议总额1,735.61，明确标注“尚未生效”。此时现行报价仍为旧金额。
5. 核对新值、来源与完整影响集合，由财务负责人确认批准。本地演示账号可使用配置的负责人身份；这不是生产SSO身份认证证明。
6. 应用完成后查看**本次变更的生效结果**：逐字段对照、金额对照、审批与前后版本均属于该提案。回到当前交付，确认总额已变为1,735.61；刷新页面应保持结果。

变更涉及商品明细时，预演和生效结果都可展开明细变化，按 `line_id` 对照新增、移除和修改的 SKU、说明、数量、单价与行金额。总额相同也会列出商品变化；纯折扣或税率变化不会额外生成一张未变商品表。预演始终标为拟议结果。

拒绝与越权由自动回放另行检查：未批准不能应用、错误负责人不能批准、拒绝后现行金额不变。演示工作区与真实客户系统隔离，没有发送客户报价或外部财务指令。

## 计算合同与实现边界

- 输入价格必须为十进制字符串，数量为正整数；禁止浮点价格、负价、非有限数、重复行ID、混币和不支持的币种。每单1–200行，数量不超过1,000,000。
- 依次计算：每行数量×单价并舍入 → 汇总行金额 → 计算并舍入整单折扣 → 计算并舍入折后价外税 → 净额加税。使用Decimal和`ROUND_HALF_UP`。输入单价保留原始精度，金额按币种最小单位输出。
- 支持GBP、USD、EUR、CNY两位小数，JPY零位，KWD三位；一个报价一种币种，不做汇率转换。
- 折扣与税率以整数基点保存，1基点=0.01%，范围0%–100%。界面接受最多两位小数的百分比。
- 当前支持整单统一折扣、折后统一价外税，不包含税法判定、含税价拆分、多税项、运费、阶梯价格或退款。这些规则只有明确业务需求与验收数据后才扩展。
- `enterprise_quote@v1` 已封装模板和历史证据保持原合同。需要金额的企业包显式使用v2，提供 `quote_basket` 和 `pricing_policy` 两个已准入来源；没有来源时不猜金额、不显示伪造零值。

计价器是现有Formation和Rebase的共同依赖。正式提交重新根据准入上下文渲染并核对金额；复核器另用有理数/整数算术验证导出证据，不将生产计价器的返回值当作它自己的测试答案。报价、来源与版本图仍在同一现有事务中提交。

## 自动回放与证据解释

```bash
.venv/bin/python scripts/run_public_quote_replay.py \
  --output ../.runtime/retail-replay-new
```

2026-09-16的固定24单回放包含355条原始明细、48份前后报价，实际生成、预演、批准、应用及独立金额核对全部通过，另有72项权限与拒绝检查。每单保存来源附件、封装包、前后报价、治理证据与数据库。

回放器默认验证保留样本的固定摘要；自定义`--sample`只检查结构、来源元数据与内部算术，不重新打开XLSX。不能单凭回放PASS宣称任意输入JSON来源真实。

每次新回放现在先写 `run-plan.json`，固定所选发票、原始行坐标、输入摘要、样本摘要和执行顺序，再启动工作流。`report.json` 和 `index.html` 在每单开始、结束时更新；直接打开 `index.html` 可查看全部样本的通过、失败、未完成、分段耗时及逐单证据链接。通过样本同时显示独立核验的变更前后GBP合计，直接使用报价金额原文；失败、未完成或金额缺失时显示“未验证”，不把受控折扣产生的金额变化称为收益。`--limit N` 仍只取既有样本顺序的前N单，计划明确记录该限制。

时间由 `time.perf_counter_ns` 围绕真实调用测得，分别保留数据准备、报价生成、提案、预演、批准、应用、拒绝和独立核对等分段。逐单总耗时包含准备、治理、验证、运行时关闭与逐单证据写出，排除样本预检、计划及汇总报告生成；不使用演示的冻结业务时钟推算耗时。报告按发票计算最近秩P50/P95，失败耗时保留在全部已启动样本中，同时列明成功分位数的样本量。

一单失败后继续其余预登记样本，错误仅记录异常类型与固定阶段代码，不写入原始异常消息。失败退出码为1；Ctrl-C在可捕获的位置保留当前与未启动样本为 `INCOMPLETE`，退出码为130。输入预检失败不会开始运行，也不会覆盖已有输出。预期的未批准/越权拒绝属于单独负向检查，不计作意外失败。

这些记录测量本机受控工作流的实际执行时间；脚本负责人批准和0秒审阅等待不代表人工劳动。没有观察到的人时、模型账单、运维成本与客户收益均标记为未测量，不补成零费用，不直接转成 `business-report` 所需的完整成本观测。该报告仍需按 [业务效果与成本观测](BUSINESS-OBSERVATIONS.md) 单独收集真实配对流程和完整费用。新回放输出与2026-09-16历史结果各自保留，不回填历史耗时。

## 全源覆盖检查

从UCI官方页面下载并解压原始XLSX后，可重新核对真实来源、逐字段重建固定24单、扫描全部合格发票，并生成HTML和JSON报告。适配器只接受固定SHA-256：`43465a06f2ccf7c8b5bd2892bc7defb52f97487934fe93b16ae4c3936424676d`。

```bash
.venv/bin/python scripts/evaluate_public_quote_data.py \
  --source '/path/to/Online Retail.xlsx' \
  --output ../.runtime/retail-review-new \
  --replay-report ../.runtime/retail-replay-new/report.json

.venv/bin/python scripts/run_public_quote_replay.py \
  --sample ../.runtime/retail-review-new/extension-sample.json \
  --output ../.runtime/retail-extension-new

.venv/bin/python scripts/run_public_quote_replay.py \
  --sample ../.runtime/retail-review-new/notation-sample.json \
  --output ../.runtime/retail-notation-new

.venv/bin/python scripts/evaluate_public_quote_data.py --annotate-only \
  --output ../.runtime/retail-review-new \
  --extension-replay ../.runtime/retail-extension-new/report.json \
  --notation-replay ../.runtime/retail-notation-new/report.json
```

最后一步将新运行的来源附件与前后报价重新读回，对照源扫描时固定的样本摘要和独立算术，写入同一评测页。它不重新扫描XLSX，也不重新执行审批。报告保留真实数据、受控规则、计算结果三者的区别。

2026-09-16全源实测：541,909行、25,900个发票编号中，15,181单满足明示完整数据筛选条件，10,719单整单排除。实际计价器支持其中15,177单、258,064行，两个规则共30,354次计算与独立有理数算法一致；4单超过200行合同，明确列为未支持。包含科学计数法原价的7张完整发票，在适配层精确展开十进制表示后，另行完成完整治理回放；原始附件保留原文。没有把`0.070000000000000007`擅自改成`0.07`。

原24单只覆盖3个国家/地区值、11个月份，最大38行；新增固定排序第25–48单全部来自英国，最大96行。这些是正确性工作负载，不能代表多企业、多地区或所有采购规则。全源计价也不是生产并发或全量治理工作流测试。退款、复杂税制、运费和真实连接器不因该结果而被视为已支持。

本演示使用本地确定性候选、SQLite和受控角色。它补齐实际计价与治理联动；不代表原生AgentTeams、在线模型、企业连接器、生产容量或付费价值已经验收。原生AgentTeams运行仍按[主Demo手册](DEMO-RUNBOOK.md)单独核对，不把历史协作记录拼接成该金额运行的证据。
