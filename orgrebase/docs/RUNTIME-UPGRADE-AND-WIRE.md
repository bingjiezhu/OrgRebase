# 暂停工作升级与浏览器传输

生产工作只有一条批准、应用和效果状态机。兼容读取历史材料不意味着旧批准可以跨版本继续执行。

## 暂停运行

预演在保存时绑定工作区、tenant、run、EnterpriseBinding 摘要、预演摘要，以及产生预演的运行实现。实现指纹包含工作流、领域契约、影响传播、证书、重建处理器、来源恢复、读取见证、批准授权和相关依赖版本。

| 情况 | 处理 |
|---|---|
| 进程重启，代码、依赖、作用域和预演均相同 | 允许继续，但仍重新验证当前授权、期限、来源和前置版本 |
| 关键代码或依赖改变 | `REPLAN_REQUIRED`，重新预演、审阅和批准 |
| 旧的待办没有运行绑定 | `REPLAN_REQUIRED`，不推测它与当前处理器兼容 |
| 已完成的历史回执 | 按原版本只读验证，不重算摘要，也不再次执行 |
| 新的外部效果尚未发出，处理器已经升级 | 拒绝第一次派发，重新准备准确的效果提案 |
| 外部效果已经进入 `COMMIT_UNKNOWN` | 保留原身份与目标屏障，仍可查询原回执；不能用升级理由新建重试 |

实现指纹是保守的兼容判定，不是任意版本之间的数据迁移引擎。不要为了减少重新审批而修改旧绑定。部署顺序是停止新执行准入、排查在途效果、显式数据库迁移、替换制品、资格检查、重新规划不兼容待办。恢复与撤回详见 [制品资格](RELEASE-CANDIDATES.md) 和 [恢复效果盘点](RECOVERY-EFFECT-INVENTORY.md)。

OAC 来源兼容修复对应本地准入策略 revision 6：只更新经核验的 OAC 源码精确指纹，既有权限和效果限制保持。产品 wheel 内的策略由 `configs/oac/runtime-admission-policy.json` 打包生成，需与 OAC 分发件一起重新构建；运行中的 Bridge 已加载旧策略，需随正常部署重新实例化。旧预览、批准和证据不自动迁移到新策略，待办应重新预演并按当前权限批准。未来发布时，CI 的 OAC 提交引用还需指向实际包含修复的明确提交；本地源码检查不代替发布提交资格。

## 两个明确的摘要协议

| 协议 | 用途 | 兼容规则 |
|---|---|---|
| `orgrebase.python-json.v1` | 已持久化对象、批准、回执和历史证据 | 原字节规则保留；不能因 JavaScript 数字格式不同重写摘要 |
| `orgrebase.jcs-safe-number.v1` | 当前 HTTP JSON 传输及新增多来源归档的浏览器校验副本 | 使用 RFC 8785 规范化并限制可接受数据域 |

传输允许普通 JSON 类型；拒绝非有限数、绝对值大于 `9007199254740991` 的数字、无效 Unicode、超过 128 层的嵌套和 Python 原始解析中的重复对象键。大整数、精确金额和十进制业务量使用字符串。Unicode 不做隐式归一化；键按 JCS 的 UTF-16 顺序排列。`1.0`、负零和指数的语言差异通过规范化处理，不能依赖重新序列化恰好相同。

成功的 JSON 响应携带 `OrgRebase-Wire-Scheme`、`OrgRebase-Wire-Digest` 和 `OrgRebase-Content-Scheme`。浏览器先复验传输摘要，再使用业务数据。传输摘要只检测传输内容的一致性；同一响应内的摘要不是签名、可信发布源或批准权。TLS、当前身份校验、数据库批准绑定和独立审计锚仍承担各自职责。

多来源归档 v3 同时保留原 `group_evidence_digest` 和显式标注协议的 `group_evidence_wire`。浏览器验证后者并核对来源、各负责人批准及唯一报价后继之间的关系；服务端仍按原模型摘要验证完整证据。

`tests/fixtures/wire-v1-vectors.json` 是 Python 与真实 Node.js 共用的冻结向量，覆盖数字边界、指数、UTF-16 键排序、无效 Unicode 和十进制字符串。暂停升级、首次效果派发及 UNKNOWN 后续查询分别有回归测试。它们证明本地兼容判定，不能代替客户制品升级演练。

规范依据：[RFC 8785](https://www.rfc-editor.org/rfc/rfc8785.html)。
