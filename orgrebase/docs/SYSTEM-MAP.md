# OrgRebase 产品真相（L0）

> 这是当前唯一的人工可读产品真相入口。[`evidence/release-facts.json`](../evidence/release-facts.json)
> 与对应独立 verifier 保留早期参考主线的机器事实；它们不证明后续源码或安装包。历史 Spec 已从可运行代码树移出。

## 一句话

**OrgRebase 是企业工作持续演化引擎：它依据 OAC 约束为每个工作任务形成最小 Agent
团队，让 Agent、Tool 和 Skill 只产生候选与证据，由确定性控制面和精确人类负责人决定什么
能进入企业规范状态，并只更新真正受影响的业务对象。**

产品要解决的仍是同一个问题：报价规则与职责变更后，制度已经更新，系统与执行却仍沿用旧规则，
并可能发生越权。产品主张保持为：**多域 Agent 基于组织快照生成候选变更，四层权威分离，
制度改一次，系统与执行同时到位。**

这定义演进方向，当前实现范围需要单独说明：可持续变更的报价前提包括发布日期、币种和产品方案；
显式采用计价模板v2的企业包还支持商品明细、整单折扣和价外税规则，沿同一批准与Rebase路径更新金额。
单币种、舍入顺序及受控数据边界见[报价计价演示](PRICED-QUOTE-DEMO.md)，不推断汇率或企业税法；
组织职责绑定仍须精确准入；部署明确启用双人移交政策后，当前负责人授权与新负责人接受共同驱动
单资源职责版本切换，事件委派仍是另一种更窄的授权。变化轮可选择本地参考解释或显式配置的
OpenAI Responses 候选，真实模型质量与用量尚待实际授权环境验收。内部来源与后继报价在同一事务生效，外部系统通过
获准效果及对账收敛；“同时到位”不代表跨数据库、CRM 与任意外部系统的原子事务。

## 唯一用户与交付

- **主用户**：企业报价变更负责人（Quote Operations Owner）；他/她接收上游变化并确保既有成果保持一致。
- **协作角色**：Product、Legal、Finance 和 GTM；每个领域由 Domain Agent 自动处理候选工作，由 Human Owner 持有本领域规范权威。它们不是四个并行产品。
- **唯一主交付**：可交付的后继 Quote，附带字段变化、审批依据、工作轨迹和可复核回执。
- **当前参考切片**：Enterprise Quote Profile；它是 MVP 验证负载，不是产品的最终边界。

## 唯一主流程

```text
一次性企业接入
企业事实 / 知识 / 权限 / 能力 / 依赖
  → OAC 候选映射与确定性校验
  → Enterprise Contract Owner 批准精确版本
  → 不可变激活绑定

变化驱动的持续工作
既有 Quote 与依赖基线
  → Quote v1 基线 Formation 把已准入领域任务与 Reviewer 编译为固定版本 AgentTeams 生命周期
  → 产品 / 政策 / 财务等上游语义变化到达
  → 来源 worker 或业务提案登记 ChangeEvent；工作台或调用方显式触发预演
  → 冻结 ChangeSet，先发现受影响领域与成果
  → 根据持久依赖与实际读取收据投影最小变化团队与最小上下文
  → 变化轮复用同一候选计划；golden 模式通过隔离的固定版本 AT 进程执行本次 ChangeSet 任务
  → 候选任务接收后独立校验契约，再完成复核任务；受控本地传输，不等于外部 Element 会话
  → 本次 run 内冻结计划
  → 变化轮只生成零写入的解释候选；Skill 版本引用不冒充实际调用
  → 确定性控制面形成最终 Preview + VMRC
  → 只通知需要规范写入的精确 Human Owner
  → 持久化暂停；批准前 canonical target writes = 0
  → 有执行权限的主体提交精确批准，控制面执行选择性 Rebase
  → Quote 后继版本 + 差异 + 回执 + 回滚点

能力演化（与业务批准分离）
运行经验候选 → 独立评测 → Skill Steward 批准 → CANARY / 拒绝 / 回滚
```

一条原则概括动态与可控的关系：**跨任务动态，单次运行内冻结；重规划必须产生新版本和原因。**

一条原则概括自动与人工的关系：**候选层默认自动，权威点精确暂停；Agent 管理领域工作，Human Owner 决定本领域什么可以成为规范状态。**

当前“自动”发生在已触发的预演内部；来源 worker 尚不负责事件到达后的自主模型调度。
日期、币种与产品变化的现行链路、带金额币种的原子变更缺口，以及与副本和外部审计的核对，
见[上游变化与数据验证复核](UPSTREAM-CHANGE-REVIEW.md)。Quote v1/v2 共用控制面，不是两套运行框架。

## 权威不可漂移

产品的四层权威是：**AgentTeams 任务与候选 → 控制面准入 → 精确 Human Owner 批准 →
StateStore / RebaseWorkflow 规范写入**。它们定义决定权，不要求拆成四个独立服务。
OAC 的 SOURCE / PLAN / EVIDENCE / BENCHMARK 是契约的数据权威分类，不替代这四条运行边界。

| 主体 | 拥有 | 不拥有 |
|---|---|---|
| OAC | 组织、事实、知识、权限、能力和交接的可移植契约 | Runtime、任务队列、业务数据库或最终批准 |
| AgentTeams | 任务创建、委派、ACK、交接、结果与执行终态事实 | 业务准入、人类批准或规范写入 |
| Agent / Model / Tool / Skill | 受限读取、执行事实、候选和证据 | 自我授权、自批、擦除 `UNKNOWN` 或直写规范状态 |
| OrgRebase 确定性控制面 | 范围准入、Formation、影响裁决、审批绑定、Apply 和恢复编排 | 代替人类 Owner 做高风险业务决定 |
| Human Owner | 对自己拥有的精确对象批准或拒绝 | 代批其他 Owner、陈旧对象或未审阅摘要 |
| StateStore / RebaseWorkflow | 原子写入后继 Quote、graph、receipt 和 pointer | 信任未验证候选 |

```text
AT completed
  != Candidate admitted
  != Reviewer accepted
  != Human approved
  != Canonical applied
```

[`release-facts.json`](../evidence/release-facts.json) 固定；新增企业路径在本地真实 PostgreSQL、HTTPS、
验证过的合成 OIDC 身份和 Dataverse 协议夹具上验收。它证明相应实现和本地协议行为，不证明客户接入、
真实员工使用或企业收益。测试数量、文档 `COMPLETE` 与 Demo 时长不能替代产品验收。

## 当前企业部署结构

- 一个租户使用专属数据库，数据库内按工作区隔离；当前每个工作区一个 Quote。运行角色不能迁移数据库或绕过 RLS。
- HTTP、CLI 和 worker 进入同一应用用例与规范写入内核。SQLite 保留本地运行与历史复验用途。
- Formation 自建事务或借用调用方事务均进入 `_commit_quote_in_transaction`，当前授权与一次独立证明验证位于幂等回执返回之前。Store 在真正 COMMIT 前再次检查当前授权、本地确定性模式的原 lease 与形成操作是否完整；外层捕获中途异常也不能提交半成品。服务端直接复用已形成回执仍重新检查当前请求授权；远端 IAM 与本地提交不是分布式原子事务。
- 来源 worker 只读外部系统；字段候选、转换和负责人映射经过精确签收后才能接收来源。
- 普通变更与多来源恢复使用相同的依赖、批准和重建规则；多来源恢复要求事件当前有效的各负责人批准各自范围，一次事务产生一个后继。职责已变化的旧事件须由新负责人重新提案和批准。
- 变化解释按冻结来源的真实领域归组，一个领域覆盖自己的全部变更；下游影响任务等待所有相关领域。未知领域不按对象名称猜测职责。
- 原生模型调用在派发前按明确价格合同预留整次预览费用，网络调用受父进程截止约束；没有使用量不明的失败冲销预留，也没有整个企业账户的月度预算承诺。
- 普通变更与来源恢复组共用持久候选尝试。详情只读呈现尝试状态、费用预留和脱敏回执；模型完成不等于独立校验、人工批准或规范应用，失败与未知不触发自动重派。
- OIDC/BFF 验证当前主体；委托绑定一个事件、原责任人、受托主体和有效期，执行前重新校验。
- 职责移交默认关闭；`mutual-consent-v1` 复用现有对象版本和唯一当前指针，不改初始 profile/pack，不创造成员或扩大目标操作权。A→B→A 不能复活旧批准，来源映射与旧 worker 也必须重新确认职责版本。
- 控制台的职责移交工作台读取可信成员和有界提案列表；现任、继任分别核对同一份冻结提案并确认，激活仍由后端复核。界面动作来自服务端当前权限投影，历史提案可按 ID 重开。
- 完成提示依据当前运行的回执投影，不从已有报价推断曾有两次变更、两次人工批准或外部交付。
- 外部写入只由效果 worker 使用凭据。目标版本冲突重新提案；结果未知时查询同一效果，不盲目重发。
- 新审计检查点使用 v2，把实际 tenant/workspace 绑定到签名；历史 v1 只在默认工作区按原合同验证。运维 HTTP CLI 与直接数据库审计 CLI 均支持显式工作区选择，不因此授予额外权限。
- 当前状态在 `StateStore.read_snapshot()` 内使用同一数据库视图，历史列表有界；完整审计单独执行。租户、工作区、数据库恢复资格仍逐次检查，只合并 SQL 往返；只读快照省去写事务才需要的独立 pointer 锁定查询。自有读范围结束后重新检查恢复资格，清理失败即隔离连接；借用写事务不结束调用者事务或取消写前锁。
- Vertex / Ollama 与通用 HTTP 模型入口用独立版本化观察记录每次物理调用，派发前保存意图，失败或中断保留未知用量；读取文件必须验证原有摘要，缺失或空摘要不能自动补成完整证据。旧 V1 回执继续用于原业务验证，旧零值不作为新成本凭证。持久观察范围限配置的运行目录，不声称覆盖企业账户所有调用。
- `business-report --evidence` 可离线核对费用文件、原始摘要、币种、分摊与模型派发覆盖；费用未知时不输出完整成本报告。凭证内部一致仍不证明真实账单或企业 ROI。
- 经验候选评测沿现有基线和候选两次实际执行，独立保存两侧观察；控制器可读取同一冻结输入下的动作差异、拒绝及未知。适用范围也是行为的一部分，历史没有观察时不反推实际动作；该诊断不改变 Skill Steward 的发布权，也不等于企业收益评分。

上述 spec2 实施范围、当次验证与未采纳的扩张见历史档案 `20260912-spec2-implementation`。恢复库先隔离，盘点外部回执和删除台账后再决定恢复写入。

## 当前不可声明

- 真实 CRM / CPQ / CLM / ERP / 知识库连接器已接通。
- 外部 IAM、真实企业员工 UAT 或真人企业审批已验证。
- 报价周期、工时、漏改率、返工率、人工升级率或 ROI 已取得企业实测改善。
- 分布式自主 AgentTeams、生产多租户、SLA / SLO、HA / DR 或容量边界已认证。
- OAC 已是行业标准，或可以零配置自动适配任意企业和流程。
- 任务协调器是一个可自由认知、自由扩权的“总控大模型 Agent”。

## 初赛非回归约束

任何优化都必须保留初赛的有效产品骨架：

1. 一个报价场景，Product / Legal / Finance / GTM 跨域协作；
2. Quote `v1 → v2 → v3` 的可见业务变化；
3. 依据实际读取和版本来源计算影响；
4. 变化所属领域的精确 Owner 审批；
5. 仅重做受影响对象的选择性 Rebase；
6. `UNKNOWN` 、越权、摘要漂移和陈旧审批失败关闭；
7. 版本化交付物、轨迹、回执和可恢复历史。

OAC、AgentTeams、Tool、Skill 和工程证据只能让这条骨架更可执行、更可验证，不得取代它。
