# 上游变化与数据验证复核（2026-09-19）

本次对照当前源码与 `OrgRebase_副本/orgrebase`，并核实用户提供的《数据源审计结论与优化筛选建议》。
该审计是待核实的证据和意见，不是实施指令。以下结论针对当前工作树，不追认旧制品的验证资格。

## 判断：保留多领域演化目标，不回滚事件架构

日期、币种和产品变化应当继续作为产品核心能力。当前不是只剩折扣计算：
`DomainPack`、`ChangeRegistry`、`ImpactEngine`、领域候选计划、Owner 审批和 `RebaseWorkflow`
仍能处理这些前提变化。公开交易演示只选了折扣作为易复算的案例，因此展示的能力比内核窄。

但“已经完整实现上游变化后自主更新所有企业系统”也不成立。当前持续重建的主交付仍为 Quote；
其他任务模板的 Formation 证明，不自动等于它们已有完整的变更、审批和交付适配器。
变化轮的领域任务目前解释已经锁定的前提与影响，业务值由准入后的来源和确定性重建器决定；
模型不能自行发明上线日期、汇率或企业政策。

| 副本到当前的变化 | 判断与处理 |
|---|---|
| 固定“日期变化→审批→币种变化→审批”的展示时间线退场 | 不恢复假定所有工作区都经历两次变化的时间线。当前记录必须来自本次真实事件与回执 |
| 显式企业绑定不再自动登记旧 fixture 的未来事件 | 保留。接入包提供现行事实，未来变化由来源同步或当前提案命令登记 |
| 公开交易脚本清空旧 `change_family/proposed_values`，仅提案 `pricing_policy` | 合理的窄数据案例，但不能代表系统范围；日期、币种和产品链需独立回归 |
| 日期、产品变化 | 当前两种 Quote 模板都保留，进入同一控制链；日期变化不得顺便改变金额 |
| 无金额模板的币种变化 | 保留并回归验证；它是币种政策字段变化，不是外汇换算 |
| 带金额模板单独改币种被拒绝 | 保留。只换币种标签、保持原数值会造出错误金额，不能通过撤销门禁“恢复功能” |

`template:enterprise_quote@v1` 与 `@v2` 是同一现行工作区架构中的两个任务合同：v2 增加商品篮子与计价规则。
它们不等于旧、新两套运行框架。本次不调用旧 `/api/demo` 路径，不复制副本服务，不改已封存数据包。

## 一套清晰的数据与权威链

```text
外部观察 / 有来源的业务提案
  → 来源与领域绑定、类型、版本、时效校验
  → 不可变 ChangeEvent（不等于已批准的新事实）
  → 显式触发预演：ImpactEngine + 依赖证明 + VMRC
  → 根据变化领域生成受限候选任务，完成独立校验
  → 对精确版本、范围和摘要作 Owner 审批
  → 同一个 RebaseWorkflow / StateStore 事务写入后继成果与证据
  → 外部效果单独执行和对账
```

来源 worker 自动读取并登记事件，**目前不会因事件到达自行调度模型预演**；预演由工作台或调用方显式触发。
预演内部自动执行所需领域候选。Quote 的变化适配器按变更对象的已准入领域归组，再由 GTM 汇总下游影响；
不承诺每次都调用所有四个领域，也不把这个专用适配器包装成任意企业的通用动态团队。
本地确定性角色任务、原生 AgentTeams 任务与实时模型调用仍按各自回执区分。

若继续实现用户期望的自动演化，下一步应在现有事件链上增加有预算、幂等、失败恢复和版本锁的预演调度，
并为新交付类型实现合同、重建器与验收；不是绕开控制面，让 Agent 自行写库。
跨币种带金额变化则需要同一批次冻结币种政策与经核定的目标币种明细、各自 Owner 批准、单次原子应用。
现有“来源重新准入组”不能未经合同设计就冒充任意多对象业务变更。本次没有仓促新增这些能力。

## 本次修复的实际数据链问题

1. **单个源字段语义失败会卡住整页同步。** 带金额币种冲突及非法日期/币种原先从
   `ChangeRegistry.register` 抛出完整性错误，整页事件和游标回滚；同页合法日期也无法被接收。
   来源适配器现在只把这三类已知、写入前的值校验失败转换为对应来源失效记录。
   原观察保留，其他合法字段继续登记，游标可推进；币种和金额不会被擅自改写，Quote 进入待复核状态。
   未知完整性错误、权限错误和存储错误仍回滚整页，不能以“部分成功”隐藏。
2. **映射能力大于连接器执行能力。** 当前 Dataverse 字段适配器处理文本，不支持商品篮子与计价规则对象。
   新映射候选和准入均明确排除这两类结构化槽；历史已确认的不支持映射也不能继续被视为可执行绑定。
   结构化提案仍可通过原有工作台提交，通用编辑能力不因连接器能力不足而被删掉。
3. **币种被阻止时看不到来源上下文。** 工作台改为按后端权威领域显示字段与不可提案标记，
   即使没有草稿，也可查看当前值、负责人和依据版本。可见不等于获得提交权限。

## 对另一份审计的取舍

| 审计主张 | 当前核实结果 |
|---|---|
| OrgWorkBench 满分不能证明 ImpactEngine 准确率 | 同意。参考 SUT 使用规则表；适合作为合同和策略对照，不是产品引擎评测 |
| Skill 的八个分类→动作案例跳过了图推导 | 同意。它们验证动作合同，不能冒充上游影响分析 |
| BPI 范围策略与真值使用同一谓词 | 同意。有效固定切片中的 100% Precision/Recall 是构造性的；已补 README 和当前界面边界 |
| 全仓无环检测、无多跳、不完整数据、时间测试 | 不成立。`test_impact_dag.py` 有随机 DAG 对独立路径枚举、环拒绝和深层图；`test_impact.py`、来源 coverage 与 runtime-clock 测试有不完整依赖、超深度和过期场景 |
| CompetitionValue 是唯一执行真实产品的链 | 不成立。ProductPath 黑盒脚本还启动 wheel 内 HTTP 服务，执行日期和币种的预演、审批与应用 |
| 49.4% 被敏感性分析证伪 | 表述过度。它是给定权重下的模型结果，不能证明企业节省。已补“八个目标全量重建”的假设分母，保留负收益情景 |
| 主讲改成 Precision 提升到 100%、BPI ABSTAIN 证明产品 UNKNOWN | 不采纳。前者仍是构造性指标；后者来自不运行产品的脚本，不能替代产品证据 |
| RFC updates→不受影响，HISTORIC/UNKNOWN→产品 UNKNOWN | 不采纳。文档关系与状态不提供具体成果的完整依赖边界或影响真值；引入新数据集不能修复语义映射错误 |

保留 BPI 原数据与封存收据；只补充可核实的指标边界。99.698% 是固定查询下的范围收缩，
不据此宣称业务因果安全或产品精度。历史材料、视频、比赛包继续代表其原始版本，未回填成新结果。
